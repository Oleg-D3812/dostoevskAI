# Data schema v2 (proposal — nothing migrated)

v2 is **normalization in the database sense**: every fact is stored once. It is *not* an optimisation:
all field names, id formats (chapter/scene/fragment/cluster ids), numbers and pipeline-computed values stay exactly as v1.
The site does no extra calculation; it only joins by character id.

Contents: `schemas/*.schema.json` (generated by `build_schemas.py`), `example/` (tiny valid data), `validate.py`, `migration-diagram.html` (field sources).

## What changes

| File | Change |
|---|---|
| `characters_full.json` | Slim master list: `id, name, short_label (null if none), kind, intro_chapter` (+ `note`). Removed: `novel`. |
| `characters_detail.json` | **New**, lazy, keyed by id: `aliases, desc, intro_desc, note` + `ambiguous` (moved from characters_full; `desc` was also in the network). |
| `character-network.json` | Nodes lose `label, short_label, desc, intro_chapter`; `title` removed. Everything else identical. |
| `emo-characters.json` | Loses `name`, `label` (→ master list) and `clusters_path / fragments_path_template / profile_path` (→ manifest). Keeps `id, color, fragment_count, chapter_count`. |
| `manifest.json` | Duplicate `schema_version`/`novel_id` and `title` removed (camelCase kept). New `files.character_index`, `files.character_details`, `files.scenes`. |
| everything else | Identical. |

`short_label` is the single short name (v1: `short_label` in network/glossary, `label` in emo-characters). Color stays a feature property in `emo-characters.json`.

## Left as is
Chapter/scene id formats, derived values, repeated counts, `clusters.display_id`, `emotion_model`, folder/file names, `help`/explorer paths.

## Known data issue (to fix separately)
Crime and Punishment: emotion character `marmeladova` is missing from `characters_full.json` and the network; `validate.py` reports it.

## Validation

```bash
python docs/schema-v2/build_schemas.py      # regenerate schemas
python docs/schema-v2/validate.py docs/schema-v2/example
```

The schemas were also run against an in-memory conversion of all four real novels (scratch prototype, not committed): everything validates except `marmeladova`.
The validator checks shapes and references only (ids exist, files exist); it never recomputes pipeline values.
